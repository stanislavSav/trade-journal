# 06 — QA and hardening

> **Depends on:** 05 · **Spec refs:** [plan §8, §9, §10](../plan.md), [catalogue.md](../catalogue.md) ·
> **Estimate:** 0.5 day

## Goal

The feature works on the owner's real devices, offline, in both languages and both colour schemes, and old data and
old app versions behave as plan §9 says.

## Context to load

- [plan §9 Risks and §10 Rollout](../plan.md).
- All hand-off logs of tasks 01–05.
- `src/state/useJournal.ts:76-85` (merge on Load backup), `src/storage/index.ts` (backup file).
- A real `trades.json` from the owner (ask; never commit it) and the last release before this feature
  (`git log`, the commit before task 01) for the old-version checks.

## Scope

**In:**

- The manual test matrix below, results written into the hand-off log (pass / fail + note).
- Fixes for what fails, each with a test where the code is pure.
- A parking-lot file for anything the owner must decide.
- Catalogue spot check: open 10 random catalogue websites and confirm the name and logo still match; update
  catalogue.md (and `catalogue.ts`) where a brand changed.
- Release note text for the owner (one paragraph, English and Ukrainian), including "Open the app once on every device,
  online, before you start tagging" (plan §10.4).

**Out:** new features. Anything found that is not a bug goes to the parking lot or plan §11.
